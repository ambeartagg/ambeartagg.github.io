App Log-In Sequence

Designing a Clear and Secure Account-Access Experience

I designed a login and account-creation sequence for Ink™, a fictional ink pen subscription app. The project focused on creating a simple, intuitive experience for new and returning users while accounting for authentication, validation, verification, password recovery, and security requirements.

ROLE

UX/UI Designer

User research, journey mapping, user flows, wireframing, interface design, and prototyping.

FOCUS

Login & Onboarding

Authentication, account creation, verification, error handling, recovery, and usability.

TOOLS

Figma · FigJam

User journey mapping, flow diagrams, wireframing, interaction design, and prototyping.

01 / OVERVIEW

Designing the Ink™ Login Experience

Ink™ is a fictional ink pen subscription company built around the idea that ink and paper can help create meaningful connections between people. For this class assignment, I was asked to design a login sequence that would allow users to access their Ink™ account.

The project began with research into login flows and the creation of a user journey map. I then developed a detailed user-flow diagram to understand the different paths a user might take through account creation, authentication, verification, and password recovery.

I translated these findings into sketches and wireframes before developing an interactive prototype in Figma. Throughout the process, I focused on creating an experience that felt sleek and interesting while remaining simple and intuitive.

02 / DESIGN CHALLENGE

Creating an Account-Access Experience

The larger Ink™ site and infrastructure had already been established, but the login experience had not yet been designed. My task was to create the sequence that would allow users to create an account, sign in, recover their credentials, and successfully reach the application.

The project brief provided specific user, security, and interaction requirements that the prototype needed to satisfy. These requirements became the foundation for my user flow and design decisions.

Account Access

Users need to be able to sign in to an existing account or create a new account if they do not already have one.

Authentication

The login sequence needs to support validated credentials and provide appropriate authentication and verification steps.

Validation & Feedback

Users should be notified when information is missing, invalid, or unable to authenticate.

Account Recovery

Users need a way to recover or reset their credentials if they forget their username or password.

Security Requirements

The password system needed to account for security requirements, including a minimum password length, restrictions involving the user's name, and the use of multiple character types.

03 / USER JOURNEY

Understanding the Experience Before Designing It

Before beginning the interface design, I mapped the user's journey through the account-creation experience. This helped me consider not only what actions users would take, but also their goals, thoughts, emotions, potential blockers, and opportunities to improve the experience.

User journey map exploring the goals, thoughts, emotions, opportunities, and potential blockers within the Ink™ sign-up experience.

Mapping the journey before designing the interface helped me think about the login experience as a complete process rather than a collection of individual screens.

04 / USER FLOW

Mapping Every Path Through the Sequence

I created a detailed user-flow diagram to visualize how users could move through the Ink™ account-access experience. The flow includes both successful and unsuccessful paths, allowing the design to account for situations where information is incorrect, verification codes are not received, or users need to recover their passwords.

User-flow diagram mapping account creation, login, verification, error states, password recovery, and successful access to the Ink™ app.

Sign Up

RETURNING USERS

RECOVERY

05 / WIREFRAMING

Starting with Structure

I began with a low-fidelity approach before developing the interactive prototype. Starting with sketches and wireframes allowed me to focus on the overall structure and functionality without becoming distracted by visual details such as color, typography, or polished interface elements.

Working at a lower fidelity also made it easier to explore different directions, identify potential usability issues, and make changes before committing to the final interaction design.

Wireframe and prototype development for the Ink™ login and account-access sequence.

DESIGN PROCESS

Low Fidelity Before High Fidelity

Beginning with a low-fidelity prototype allowed me to focus on structure and functionality first. It encouraged me to explore different design directions, make quick changes, and identify potential usability issues before investing in more detailed interface work.

06 / FINAL DESIGN

The Ink™ Account-Access Experience

The final prototype brings the different paths identified during the research and flow-mapping stages together into a cohesive login sequence. I kept the interface simple while providing clear feedback and recovery options throughout the experience.

01 / LOGIN

Clear Account Entry

The login screen provides a straightforward entry point for returning users while also giving new users a clear path toward account creation.

02 / VALIDATION

Communicating Login Errors

The sequence includes an error state for situations where login information cannot be authenticated. This provides feedback instead of leaving the user uncertain about what happened.

03 / ACCOUNT CREATION

Creating a New Account

New users can enter the information required to create an Ink™ account and begin the verification process.

04 / ERROR HANDLING

Preventing Invalid Account Information

The account-creation flow includes validation feedback so users can identify and correct problems with the information they entered.

05 / VERIFICATION

Choosing a Verification Method

Users can choose how they would like to receive their verification code before continuing through the authentication process.

06 / CODE ENTRY

Completing Verification

The user enters the verification code they received to confirm their account or authentication attempt.

07 / VERIFICATION FEEDBACK

Handling Verification Problems

The prototype accounts for additional verification states so users have a clear path when the expected code is not immediately available or the process needs to continue.

08 / ACCOUNT RECOVERY

Recovering a Forgotten Password

Users who forget their password can begin a recovery process directly from the account-access experience.

09 / PASSWORD RESET

Returning Users to Their Account

The password-reset sequence provides a path for users to establish a new password and return to the login experience.

10 / CONFIRMATION

Confirming Successful Account Creation

A dedicated confirmation state communicates that the account has been successfully created and provides feedback before the user continues into the app.

11 / COMPLETION

Reaching the Ink™ App

The sequence ultimately brings successfully authenticated users into the Ink™ home screen, completing the account-access flow.

07 / ERROR & RECOVERY

Designing Beyond the Happy Path

One of the most important parts of the project was considering what happens when the ideal path does not work. Rather than designing only the successful login and sign-up sequence, I incorporated states for incorrect information, verification problems, and forgotten passwords.

Invalid Information

Users receive feedback when the information they provide cannot be accepted.

Verification Problems

The flow accounts for verification situations where a code may not be received or the user needs another attempt.

Password Recovery

A dedicated recovery path allows users to reset their password rather than becoming stuck outside their account.

08 / HCI & DESIGN DECISIONS

Turning the Flow Into an Usable Interface

The assignment required me to explain how HCI principles informed the design and refinement of the prototype. The journey map and user-flow diagram helped me identify where users would need clear choices, feedback, and opportunities to recover from errors.

Clear Choices

The initial experience separates the paths for logging in and creating a new account so users can identify the action that applies to them.

Immediate Feedback

Validation and confirmation states communicate what happened after the user submits information.

Error Recovery

Users are given paths forward when information is incorrect, verification needs to be repeated, or a password has been forgotten.

Consistent Interaction

Repeated patterns across the sequence help the different screens feel like parts of one continuous experience.

09 / PROTOTYPE DEVELOPMENT

From Wireframe to Interactive Prototype

Working through the wireframe before building the interactive prototype changed how I approached the design. I had previously created a wireframe for another class, but this project felt different because I had already worked through a user journey map and user-flow diagram before beginning the interface.

Those earlier steps gave me a clearer understanding of what the experience needed to accomplish. Moving from low-fidelity structure into the interactive prototype helped me visualize how the Ink™ experience could actually work for users.

11 / REFLECTION

Designing With a More Informed Process

This project reinforced the importance of starting with the structure of an experience before focusing on its visual appearance. Beginning with research, a user journey map, and a user-flow diagram helped me feel much more informed while creating the wireframe.

Moving from low-fidelity design into the interactive prototype also gave me an opportunity to think more critically about how users would actually move through the experience. Instead of considering each screen independently, I could evaluate the login sequence as one connected interaction.

Overall, the project helped me better understand how early UX artifacts can guide interface decisions and make the prototyping process more intentional.
